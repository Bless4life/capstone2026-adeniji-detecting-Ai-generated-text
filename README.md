# capstone2026-adeniji-detecting-Ai-generated-text
**Name: Blessing Adeniji**
**Msc Artifical Intelligence capstone project.**
**Topic:** Detecting AI-Generated Text (Deep Fake detection in text). The goal is to identify human content and AI generated text using Large language models LLM.

This project investigates whether transformer architecture (encoder vs. decoder) affects the detection of AI-generated text, using the Ettin model suite, the first openly available set of encoder/decoder pairs trained with identical data and parameter counts. It is a controlled scientific comparison, not an attempt to build the best possible detector. 

*Research questions*: (1) how accurately do fine-tuned encoder and decoder models detect AI text? (2) do they generalise to unseen domains and generators? (3) what characterises the texts they get wrong?

**Key Findings**:
- Architecture does not matter: At matched size, encoder and decoder differ by no more than 0.15 percentage points in-domain. This results was observed at both 68M and 400M parameters (a 6× scale difference).
- Trainind data diversity : Models fine-tuned on generator-diverse data (MAGE, RAID) generalised 30–40 percentage points more effectively to unfamiliar text than those trained on a single generator.

**Models compared**
|Model | Parameters | Architecture |
|Ettin-encoder-68m | 68M | encoder |
|Ettin-decoder-68m |68M	| decoder |
|RoBERTa-base |	125M |	encoder |
|ModernBERT-base	| 149M	| encoder |
|Ettin-encoder-400m	| 400M	| encoder |
|Ettin-decoder-400m | 400M	| decoder |

DeBERTa-v3-base (184M) was planned but could not be trained stably in this environment and then was substituted with RoBERTa-base but later substitute with Ettin encoder-400m and decoder-400m

**Datasets**:
Each balanced 50/59 and split 70/15/15
- RAID: 11 generators across 11 domains
- ChatGPT Research Abstracts: GPT-3.5, academic
- GPT-Wiki-Intro: GPT, encyclopedic
- MAGE: 27 generators across 10 domains

Note: Human-vs-Machine was excluded after it was found to repackage two of the above. MAGE's inverted label convention was troubleshooted and corrected

**Repository structure**
```├ data_exploration.ipynb - Data loading, cleaning, balancing, splits ├ finetuning_small_models.ipynb ettin-encoder-68m and ModernBERT-base (4x4 matrices) ├ Ettin_encoder_vs_decoder.ipynb Ettin-decoder-68m (4x4 matrix) - core comparison. ├ spotcheck_larger_models.ipynb DeBERTa-v3 (failed) and RoBERTa-base spot-check ├ ettin_encoder_decoder_400m.ipynb encoder/decoder at 400M ├ error_analysis.ipynb Error analysis (RQ3) ├ 100_sample_text_evaluation.ipynb 100-text sample comparison across all models ├ all_models_evaluation_results.csv all evaluation results ├pyproject.toml / uv.lock Environment (managed with UV) ├README.md```

Trained models and dataset splits are excluded from version control due to size, but are regenerated by running the notebooks in order.

Python 3.12 managed with UV: PyTorch, HuggingFace Transformers, Datasets, scikit-learn, pandas. Trained on an NVIDIA RTX 5060TI(16GB). CUDA 12.8, with BF16 mixed precision for larger models

**Reproducing the results**
Run the notebooks in order. `data_exploration.ipynb` builds the splits; the fine-tuning notebooks train the models and append to `all_models_evaluation_results.csv`; the analysis notebooks produce the error analysis and sample comparison. All experiments use a fixed seed (42), a 512-token max length, and an identical protocol (3 epochs, learning rate 2e-5, effective batch size 16). Single run per configuration.
